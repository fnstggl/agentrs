# H0 - Tier 1 rapid scientific environments: foundation (`crucible.rapid`)

Workstream H, wave 1. Implements INTERFACE_CONTRACTS section 8: the structured action interface, the RapidEnv
protocol and `make`, the versioned registry of 28 causal primitives, a structural generator, five engines (four of
the eight new kinds of Part 7.3 plus the generator's compositional engine), fingerprints with a distance, the ten
Part 7.4 admission checks with evaluator-side oracles, 29 families over all ten capability categories, the 4.0
numeric lever view, a vectorised batch path and a kernel-hosted twin.

## What exists

| module | what it is | side |
|---|---|---|

| `engines/` | `primitive_graph`, `discrete_event`, `graph_dynamical`, `state_machine`, `search` on the contract in `engines/base.py` | world |

| `fingerprints.py` | `instance_fingerprint`, `family_fingerprint`, `distance`, `counted`, `nearest`, `legacy_fingerprint` (4.0 families) | evaluator |
| `oracles.py` | search on realised noise (schedule CEM, receding horizon), privileged scripted references, policy search on forks | evaluator |

`crucible.rapid.fingerprint()` and `crucible.rapid.admit()` import them only when called.

## How to use it

```python
from crucible import rapid
env = rapid.make("hc_confounded", seed=3, horizon=80, observation_noise=0.5)
obs = env.reset()                          # Observation: t, agent, numbers, arrays (history.*), text, tools, ...
r = env.step({"kind": "levers", "values": {name: 2.0}})   # one tick; r = {observation, result, events}
env.step({"kind": "sequence", "steps": [...]})            # several actions in one tick
env.outcome()                              # evaluator side only
rapid.families.REGISTRY["net_routing"]     # engine, category, split, partition, fingerprint, doc, distinct_because, ...
rapid.admit("net_routing", seeds=(0, 1, 2))                # evaluator side
```

Multi-participant worlds (`coop_split_info`) take `step({"a0": action, "a1": action})` and return `observations`
and `results` per participant. 4.0 learners: `MechVecEnv([mechview.make_task(f, s) for ...])` with any
`crucible.research.learners` learner; `make_task(f, s, validate=True)` adds the private default/reference nets.
Batched: `BatchRapid("net_routing", range(256)).step(values)`. Kernel twin: `mechview.kernel_world(f, s)`.
CLI: `PYTHONPATH=src python -m crucible.rapid report` (counts), `... families --json out.json` (registry with the
measured nearest family and differing fingerprint components for each family).

## The 28 primitives

linear_nonlinear, threshold, saturation, non_monotonic, complementarity, substitution, multiplicative,
hidden_confounding, delay, stock, decay, hysteresis, feedback, path_dependence, network_effect, congestion,
resource_competition, strategic_interaction, partial_observability, state_dependent_effect, regime_change,
adaptive_opponent, measurement_noise, missing_observation, selection_effect, cascading_failure, endogenous_demand,
learning_behaviour. Each is version 1.0 with a JSON parameter schema, a batched implementation that never mutates
its state, declared random draws per tick, and a characteristic-behaviour check (e.g. hysteresis: input 2 gives 0
on the way up and 1 after a peak; confounding: passive correlation 0.95 with slope > 1, interventional slope ~0;
delay: an impulse at t=3 appears exactly at t=8; path dependence: the same pushes in a different order lock in at
opposite ends). Engines reuse them: threshold and network_effect in contagion, cascade in grid failures, congestion
in routing latency, the power form of linear_nonlinear for machine wear.

## Engines

* `primitive_graph` - causal graphs of primitives (levers with a natural regime for history, discrete decisions,
  lagged weighted ports, feedback through lags, channels, on-demand sensors, designed experiments on a pilot copy).
  Vectorised over a batch with per-instance parameters.
* `discrete_event` - continuous-time event queue (heapq) within ticks: tandem queues, Weibull machine failures and
  service, Poisson demand with lead-time replenishment and expiring lots. Exact time-weighted integration.
* `graph_dynamical` - state on explicit networks: two-hop fluid routing with shared hidden bottlenecks
  (vectorised), threshold contagion on a block graph, load-shedding cascades with an interdependent control layer,
  link failures with connectivity of demand pairs (union-find).
* `state_machine` - hidden finite states with action-dependent categorical transitions: Markov regimes, fault
  states with noisy tests, a staged process with irreversible traps and a costly inspection.
* `search` - exhaustible opportunities with costly noisy information: smooth value fields, feature-linear items with
  distractors, a growing tool catalogue (the action space changes), and a two-participant split-information
  search with joint commitment.

## Admission (Part 7.4)

consistency, conservation, controllability, achievable, informative, identifiability, no_dominant_strategy,
difficulty, no_leakage, distinct. Statistical checks must pass on 2 of 3 seeds, the others on all. Each check
rejects at least one deliberately broken control world in `tests/v5/test_gate_SP_7_4.py` (dominant constant,
leaked threshold, inert lever, renamed copy, negative money flow, global randomness, blind observations).

## Limitations

* Counts are below the Gate M thresholds: 21 admitted training families (60 required), 7 evaluation families (20),
  29 families with intervention tests / feasibility validation (80). Four of the eight Part 7.3 engine kinds exist
  (executable program, multi-agent strategic, scientific experiment, planning/resource are the next wave).
* Families were tuned against admission seeds 0-2; on held-out seeds `des_bottleneck` and `dl_short_term_damage`
  fail the difficulty check (the scripted reference is either worse than the default or matches the oracle) and
  `net_cascade` fails on both seed sets.
* The difficulty check relies on scripted references, some generic (best constant action found over practice
  episodes); a family can fail because its reference is weak, not only because it is too hard.
* Oracles are search-based upper references on the realised noise, not proven optima.
* RapidEnv cash may go negative (no fallback); the 4.0 lever view and the rig apply 4.0's money rules. Program
  actions are recorded in the result but a RapidEnv run is not an event-sourced log; the kernel twin exists for
  lever families through `rig` only (no kernel module for structured actions yet).
* The informativeness check is a between/within variance ratio (and hidden-state predictability for state
  machines and the joint search); it shows observations depend on the hidden instance, not that a learner can use
  them.
