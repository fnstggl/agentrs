# E1: content consumption and browsing calibration

Workstream E1 grounds the population's content-consumption and browsing behaviour in two public datasets,
KuaiRand-Pure (Kuaishou short-video app, with randomly exposed videos) and MIND-small (Microsoft News). It also
provides the calibration package skeleton that E2 and later workstreams register into: datasets, the fitted-model
registry, portable predictors, the fitting library, the gate audit and the v5 fidelity-register checks.

## What exists

| path | what it is |
|---|---|
| `src/crucible/calibration/datasets.py` | dataset recipes: URL, SHA-256 of every file (and of extracted files), schema, licence, provenance; `datasets()`, `acquire()`, `verify()`, `validate_schema()`, `register()` |
| `src/crucible/calibration/registry.py` | `FittedModel`, `load("name@version")` (verifies every checkpoint hash), `list_models()`, `save_model()`, the `DOMAINS` and `IDENTIFICATION` vocabularies |
| `src/crucible/calibration/predictors.py` | NumPy predictors loaded without pickle: constant, logistic, gradient-boosted trees (exported from scikit-learn), monotone quantile network, binned quantiles, gamma-Poisson; `register_kind()` for other kinds |
| `src/crucible/calibration/metrics.py` | log loss, Brier, ECE and reliability tables, AUC, impression AUC / MRR / nDCG, pinball loss, PIT, coverage, Wasserstein, KS, Poisson deviance, user-cluster bootstrap |
| `src/crucible/calibration/fitlib.py` | candidate fitting, the prespecified selection rule, reports, model cards; refuses to fit without a committed, unmodified evaluation plan |
| `src/crucible/calibration/kuairand.py`, `mind.py` | feature pipelines (history features from earlier days / hours only) |
| `src/crucible/calibration/fit_e1.py` | fits, compares and registers the six E1 models exactly as the plan says |
| `src/crucible/calibration/reproduce.py` | recomputes each E1 model's held-out metric from data + checkpoint with `load` only |
| `src/crucible/calibration/audit.py` | Gate F and SP-5.5 measurements from whatever is registered |
| `src/crucible/calibration/fidelity.py` | the v5 fidelity register: parses `docs/v5/FIDELITY_REGISTER.md`, maps the 4.0 register, computes the important mechanisms, checks records |
| `docs/v5/calibration/plans/E1_evaluation_plan.{json,md}` | the prespecified plan (committed in d6f4767, before any fit) |
| `docs/v5/calibration/models/<name>/` | `model_card.json` + `params.npz` for each fitted model |
| `docs/v5/calibration/reports/<name>.{json,md}` | held-out evaluation reports |
| `docs/v5/calibration/DATASETS.md` | dataset recipes, checksums, licences, provenance in prose |

## How to use a fitted model (world code)

```python
from crucible.calibration import load
m = load("content_consumption@1")          # verifies SHA-256 of the checkpoint; NumPy only
p = m.predict(X)                            # X: [n, len(m.features)] ordered as m.features
m.card["feature_map"]                       # how each simulator quantity maps onto each input
m.card["feature_quantiles"]                 # training quantiles of each input, for quantile mapping
w = load("watch_duration@1").sample(X_watch, rng)   # one draw of log1p(watch seconds) per row
rates = load("session_rate@1").predictor.draw_rates(n, rng)   # individual session propensities
```

Draw decisions with the world's seeded generator (`ctx.rng(...)`); the models are deterministic functions.
Scale-dependent inputs (activity counts, raw text cosine) should be mapped by quantile (`feature_quantiles`), not by
value: the datasets count only part of each person's activity (KuaiRand logs only pool videos), and a different
encoder gives cosines on a different scale. Scale-free inputs (rates, shares, per-capita popularity, within-slate
z-scores, ages, durations) map directly.

## Reproducing

```bash
cd crucible
PYTHONPATH=src python -c "from crucible.calibration import acquire; acquire('kuairand_pure'); acquire('mind_small')"
PYTHONPATH=src python -m crucible.scale.slots --cpu 4 --label "ws-E1: fit" -- \
    env OMP_NUM_THREADS=4 PYTHONPATH=src python -m crucible.calibration.fit_e1 --models content,watch,return,session,news
PYTHONPATH=src python -m crucible.scale.slots --cpu 2 --label "ws-E1: gate F" -- \
    env OMP_NUM_THREADS=2 PYTHONPATH=src python -m pytest -q tests/v5/test_gate_F.py tests/v5/test_gate_SP_5_4.py tests/v5/test_gate_SP_5_5.py
PYTHONPATH=src python -m pytest -q tests/test_v5_calibration_core.py      # unit tests, no data needed, ~10 s
```

The fit takes about 6 minutes with 4 threads (MIND features about 1 minute); the gate F module about 5 minutes
(it rebuilds the features and recomputes every held-out metric with the NumPy predictors).
