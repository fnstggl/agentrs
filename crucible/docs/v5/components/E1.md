# E1: content consumption and browsing calibration

Workstream E1 grounds the population's content-consumption and browsing behaviour in two public datasets,
KuaiRand-Pure (Kuaishou short-video app, with randomly exposed videos) and MIND-small (Microsoft News). It also
provides the calibration package skeleton that E2 and later workstreams register into: datasets, the fitted-model
registry, portable predictors, the fitting library, the gate audit and the v5 fidelity-register checks.

## What exists

## How to use a fitted model (world code)

```python
from crucible.calibration import load
m = load("content_consumption@1")          # verifies SHA-256 of the checkpoint; NumPy only
p = m.predict(X)                            # X: [n, len(m.features)] ordered as m.features
m.card["feature_map"]                       # how each simulator quantity maps onto each input
m.card["feature_quantiles"]                 # training quantiles of each input, for quantile mapping
w = load("watch_duration@1").sample(X_watch, rng)   # one draw of log1p(watch seconds) per row
rates = load("session_rate@1").predictor.draw_rates(n, rng)   # individual session propensities
```

Draw decisions with the world's seeded generator (`ctx.rng(...)`); the models are deterministic functions.
Scale-dependent inputs (activity counts, raw text cosine) should be mapped by quantile (`feature_quantiles`), not by
value: the datasets count only part of each person's activity (KuaiRand logs only pool videos), and a different
encoder gives cosines on a different scale. Scale-free inputs (rates, shares, per-capita popularity, within-slate
z-scores, ages, durations) map directly.

## Reproducing

```bash
cd crucible
PYTHONPATH=src python -c "from crucible.calibration import acquire; acquire('kuairand_pure'); acquire('mind_small')"
PYTHONPATH=src python -m crucible.scale.slots --cpu 4 --label "ws-E1: fit" -- \
    env OMP_NUM_THREADS=4 PYTHONPATH=src python -m crucible.calibration.fit_e1 --models content,watch,return,session,news
PYTHONPATH=src python -m crucible.scale.slots --cpu 2 --label "ws-E1: gate F" -- \
    env OMP_NUM_THREADS=2 PYTHONPATH=src python -m pytest -q tests/v5/test_gate_F.py tests/v5/test_gate_SP_5_4.py tests/v5/test_gate_SP_5_5.py
PYTHONPATH=src python -m pytest -q tests/test_v5_calibration_core.py      # unit tests, no data needed, ~10 s
```

The fit takes about 5 minutes with 2 threads (MIND features about 1 minute); the gate F module about 5 minutes
(it rebuilds the features and recomputes every held-out metric with the NumPy predictors).

## Measured results (held-out test splits, fit at d86f683, plan d6f4767)

Every model was selected on validation among the prespecified candidates and confirmed on test; in all six the kept
model is a learned model that beats the best simple baseline. Intervals are 95% user-cluster bootstrap intervals
(200 resamples).

| model | data, identification | kept | primary metric: kept vs best baseline | other held-out metrics |
|---|---|---|---|---|
| content_consumption | KuaiRand random-exposure log, randomised exposure | GBDT fitted on random exposure (400 trees) | log loss 0.4426 [0.434, 0.453] vs 0.4779 popularity (difference -0.035 [-0.039, -0.032]) | AUC 0.698, ECE 0.006, Brier 0.140, mean 0.180 vs 0.186 observed; 89,752 rows of 3,805 held-out users, 05-03..05-08 |
| content_consumption_feed | KuaiRand standard log, observational | GBDT | log loss 0.6238 [0.617, 0.632] vs 0.6650 | AUC 0.708, ECE 0.006; 10,229 rows of 2,688 held-out users |
| watch_duration | KuaiRand both logs, observational | 2x32 monotone quantile network | mean pinball 0.1294 [0.1275, 0.1311] vs 0.1378 duration-decile quantiles | PIT KS 0.011, 80% / 90% coverage 0.796 / 0.896, Wasserstein 0.48 s, view-rate error 0.004, completion error 0.011 |
| return_daily | KuaiRand both logs, observational | GBDT | log loss 0.5617 [0.551, 0.571] vs 0.6103 own-rate rule | AUC 0.704, ECE 0.026; 4-day forward simulation of held-out users: active-day distribution TV 0.048 (rule 0.092, constant 0.236) |

### What the randomised exposure shows

The observational choice models, scored on random-exposure rows of held-out users, are badly miscalibrated: they
predict a 0.47-0.50 consume rate where 0.18 is observed (ECE 0.29-0.32, log loss 0.65-0.69, worse than a constant),
and they rank worse (AUC 0.66 against 0.70 for the model fitted under random exposure). A single intercept shift
fitted on random-exposure data removes most of the miscalibration (log loss 0.456, ECE 0.013) but not the ranking
gap. The coefficients differ in kind, not just in level (standardised logistic coefficients, observational vs
random): the item's past consume rate 0.35 vs 0.02, per-capita popularity 0.03 vs 0.21, topic affinity (lift) 0.02
vs 0.16, item age -0.08 vs 0.00. Under the production recommender an item's past consume rate stands in for the
recommender's own selection; among randomly shown items what matters is how many people watched it and how close it
is to the individual's topics. This is why the population's choice rule is `content_consumption` (randomised
exposure) and the observational fit is registered separately as a learned-engagement target for recommenders.

### Repeat consumption

Re-exposure to an item the individual already consumed is rare in KuaiRand-Pure: 145 standard-log rows (consume
rate 0.48 against 0.53 for first exposures) and 8 random-exposure rows. `item_played_before` is an input of the
choice models, but its effect is weakly identified; no separate repeat-consumption model was fitted.

## Simulator feature mapping

Every card carries `feature_map` (one sentence per input) and `feature_quantiles` (training quantiles). The
mapping the population workstream should use:

* choice models: `user_click_rate` and `item_click_rate` are smoothed consume-per-exposure rates (pseudo-count 20 at
  the card's `prior_rate`); `item_log_pop_7d` is views per 1,000 active individuals over 7 days (per capita);
  `user_tag_share` / `user_tag_lift` are the share of the individual's past views in the item's topic and its log
  ratio to the population share (topic = primary tag here; nearest topic centroid of the content embedding in the
  simulator); `creator_familiarity`, `item_seen_before`, `item_played_before` come from the individual's history;
  `user_log_plays_7d` needs quantile mapping (the dataset logs only pool-video plays).
* `watch_duration`: the same inputs plus `consumed` (the choice draw); `sample()` gives log1p(watch seconds); a view
  is watch >= min(30 s, half the duration).
* `return_daily`: activity counts of the previous 7 days; `log_rows_7d` and `log_sessions_7d` need quantile mapping.
* `session_rate`: draw each individual's extra-session rate with `draw_rates`, update with `predict([count,
  active_days])` as behaviour accumulates.
* `news_click`: `text_cos_z` (within-slate z-score of the text affinity) is encoder-independent; raw `text_cos` and
  `pop_log_clicks_per_1k` should be quantile-mapped; shares, rates, ages and slate size map directly.

## Limitations

* All six models are fitted on two platforms, two months and two selected user samples (Kuaishou users chosen by
  the KuaiRand authors, April-May 2022; Microsoft News users sampled by the MIND authors, November 2019). Each card's
  `limits` says what the simulator may and may not infer from them.
* Only `content_consumption` rests on randomised exposure. Even there the feature effects are associations among
  randomly shown items: nothing here identifies what changing an item's popularity or an individual's interests
  would cause. All other models are observational.
* KuaiRand-Pure logs only interactions with the 7,583 pool videos, so absolute activity (plays, active days,
  sessions) is undercounted; activity inputs must be mapped by quantile. The random-insertion rate rose during the
  period, which shows as upward drift in held-out return and session rates (session count calibration error 0.43;
  the ordering of individuals is right, the level is low).
* Item ages cover 0-30 days only, because every pool video was uploaded on 2022-04-09..11; age is confounded with
  calendar time.
* The watch-duration model is pooled over both logs and is best on non-selected exposures; on recommender-selected
  exposures alone it under-predicts long watches (PIT KS 0.084, completion error 0.05). Replays beyond about four
  times the duration are not reproduced (quantile levels 2%-98%).
* MIND's text affinity uses TF-IDF + LSA computed here, not the semantic workstream's encoders; the within-slate
  z-score keeps the fitted relation usable with another encoder.
* MIND-small came from a third-party Hugging Face mirror because the official copy is gated (licence click-through)
  and no credential was available; the files match the official statistics, and the licence is recorded.
* The portable tree predictor runs at about 40 microseconds per row for a 400-tree model in NumPy (100,000 rows in
  about 4 s); callers should batch.
* Gate F's F.2 (randomised commercial response) and F.7 (three checksummed datasets) depend on E2's models and
  datasets; with E1 alone they fail.
