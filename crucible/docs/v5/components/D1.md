# Component D1: content encoders and media tools (`crucible.semantic`)

Workstream D1, Crucible 5.0. Contract: [INTERFACE_CONTRACTS.md](../INTERFACE_CONTRACTS.md) section 4 (`encode`,
`encoder_info`, `cache_key`). Spec: MASTER_SPEC Parts 4.2 (actual content artifacts, creator tools), 4.3 (semantic
content understanding), 13.5 (multimodal caching), Gate E. Requirements: E.1, E.2, E.3 (measurement helper and test;
the participants are workstreams B/C), E.4, E.5, E.n1. Workstream D2 owns the shared inference service and the
semantic participants in the same package (`service.py`, `participants.py`).

## The encoders

| modality | encoder id | models (pinned revision) | executed params | dim |
|---|---|---|---|---|
| text | `crucible.text.minilm-l6-v2` | sentence-transformers/all-MiniLM-L6-v2 @1110a243 | 22.7M | 384 |
| image | `crucible.image.clip-vit-b32` | openai/clip-vit-base-patch32 @37000f5c (safetensors) | 87.8M (vision tower + projection; the text tower is loaded, never run) | 512 |
| audio | `crucible.audio.ast-audioset+whisper-tiny` | MIT/ast-finetuned-audioset-10-10-0.4593 @f826b80d, openai/whisper-tiny @169d4a43, MiniLM | 147.1M | 1152 |
| video | `crucible.video.clip-frames+ast+whisper+temporal` | CLIP + AST + Whisper-tiny + MiniLM | 234.9M | 3208 |
| code | `crucible.code.struct32+minilm-l6-v2` | MiniLM | 22.7M | 416 |

Weights on disk: 1.19 GB (MiniLM 91 MB, CLIP 605 MB, AST 346 MB, Whisper-tiny 151 MB) of the 3 GB budget, all
safetensors, in the shared HF cache (`$HF_HOME`, default `/workspace/.hf_home`). Loading is `local_files_only`:
the simulation never touches the network. `python -m crucible.semantic.encoders fetch` downloads exactly these files.

**Why AST for audio.** It is trained on AudioSet (527 classes: speech, music, instruments, tones, environmental
sound), so its pooled embedding separates the kinds of sound content creators publish; it is 86.6M parameters and
346 MB in safetensors, against 153M / 614 MB (pickle only) for CLAP. Its AudioSet "Speech" posterior gates the
transcript: Whisper invents words for music and tones, so only clips the AST hears as speech are transcribed. CLAP's
advantage, a text-aligned audio space, is not needed because spoken content reaches the text space through the
transcript.

**Composite vectors.** Audio, video and code vectors concatenate L2-normalised blocks scaled by weights whose squares
sum to one, so the cosine similarity of two vectors is the weighted mean of the blocks' cosines: audio = 0.64 sound +
0.36 spoken content; video = 0.55 pictures (4 ordered segments) + 0.35 soundtrack + 0.10 temporal statistics; code =
0.75 declared purpose + 0.25 structure.

## How to use it

```python
from crucible.semantic import encode, encode_many, encoder_info, cache_key

v = encode(world, ref, "video")                 # float32 [3208]; no ctx: nothing is recorded
v = encode(world, ref, "video", ctx=ctx)        # inside a handler/process: recorded in the world (see below)
M = encode_many(world, refs, "image", ctx=ctx)  # [n, 512], one batched forward pass for the misses
v = encode(world, ref, "text", ctx=ctx, data=raw_bytes)   # when the caller already holds the bytes (must hash to ref)

from crucible.semantic.encoders import encode_bytes
v = encode_bytes(open("clip.mp4", "rb").read(), "video")   # no world (tools, calibration, offline analysis)
```

Where a vector comes from, in order: (1) the world's own record (`embed` module, table `embeddings`), so replay,
regeneration, snapshots and forks see exactly the recorded vector even if the hardware or library changes; (2) the
process memory cache, then the disk cache shared by all participants and worlds on the machine (a video is encoded
once, never per viewer); (3) the models, on the artifact's bytes from `crucible.substrate.artifacts.get`.

**Recording.** With `ctx`, a vector not yet recorded in the world goes through
`crucible.substrate.inference.recorded` (array output stored as an array blob when the world has the `artifacts`
module; otherwise a JSON record), falling back to the kernel's `ctx.external` with the same record shape
(`{model_id, model_hash, inputs_digest, output}`, kind `infer.embed.<modality>`) where the substrate is not installed.
The model hash is the SHA-256 over the encoder version and the hub SHA-256 of every weights file it runs. When the
`embed` module is installed, one `embed.recorded` event per batch stores the vectors in its table; later reads in the
same world never run a model.

**Cache keys.** `cache_key(ref, modality) = "{ref}|{encoder_id}@{version}|{preprocessing_hash}"`. The version is the
pinned revisions of the models plus a code version; the preprocessing hash covers every preprocessing setting. New
content (a new SHA-256), a new model revision, a code change of the encoder or a different preprocessing all give a
new key, so the cache never returns a stale vector. Disk entries carry the full key and the SHA-256 of the vector and
are verified on every read (a tampered or misfiled entry is dropped and recomputed).

**Devices.** Models run on the GPU when the slot provides one, else on CPU (`CRUCIBLE_ENCODER_DEVICE=cpu|cuda|auto`
overrides), in fp32 on both; `tests/test_v5_semantic_encoders.py::test_cpu_execution_agrees_with_this_process` checks
that a CPU process and a GPU process agree (cosine > 0.9995). Always run through the slot scheduler, e.g.
`python -m crucible.scale.slots --cpu 2 --gpu-mb 3000 -- ...` (measured peak: 1.5 GB allocated).

## Media tools (creators)

Pure functions in `crucible.semantic.media` (bytes in, bytes out): `render_text_image`, `render_html_image` (a
bounded deterministic layout engine for headings, paragraphs, lists, quotes, code, links, emphasis and colours;
`engine="chromium"` takes a headless-Chromium screenshot with JavaScript and the network disabled), `draw_scene`,
`process_image` (resize, crop, rotate, colour, blur, noise, text overlay, re-encode), `synth_speech` (flite, five
voices), `synth_tone`, `synth_melody` (notes, chords, drums), `synth_noise`, `mix`, `assemble_video` (images + audio,
fades, letterboxing), `transcode` (wav, flac, mp3, ogg, opus, m4a, mp4, webm, mkv; quality, size, frame rate, trim),
`probe`, `decode_audio`, `extract_frames`, `gray_sequence`.

Bounds: FFmpeg runs in a private temporary directory with a wall-clock timeout, CPU-time, address-space and file-size
rlimits and one thread; inputs are limited to the `file`/`pipe` protocols and an allow-list of demuxers, so a
crafted playlist or concat list cannot make FFmpeg read other files or open connections (tested). Images are decoded
under a 40-megapixel limit; outputs are limited to 32 MiB (the artifact limit). Outputs are bit-exact (no random Ogg
serials or Matroska UIDs, no version tags): the same inputs give the same bytes, verified for every format.

Kernel module `media` (host `media`, needs `artifacts`): `media.render_text`, `media.render_html`, `media.draw`,
`media.edit_image`, `media.speak`, `media.synth`, `media.make_video`, `media.transcode`, `media.probe`. Each run is
recorded (the record holds the output REF, MIME type and size) and its output is stored as an artifact owned by the
caller with the inputs as parents. Inputs must be readable by the caller (unreadable looks like missing). In
regeneration the tool is re-run and its output verified against the recorded REF.

## Limitations

* **E.3 needs participants.** The measurement exists (`effects.py`: controlled two-world experiment, paired
  sign-flip permutation test, Bonferroni over pairs) but no participant consumes content yet. Workstreams B/C register
  a probe (`effects.register_probe(name, make_world, run, modality=...)`) from their `modules.py`; until then
  `test_E3_...` records p = 1.0 and fails.
* **Substrate dependency.** `encode(world, ref, ...)` without `data=` reads bytes through
  `crucible.substrate.artifacts.get`, and the `media` module stores outputs with `artifacts.put`; neither exists on
  the integration branch yet. The code follows INTERFACE_CONTRACTS 1.1/1.7 exactly; `tests/test_v5_semantic_media_world.py`
  (3 tests) passes against workstream A's in-progress tree and fails here until A is merged. Without the substrate,
  recording falls back to `ctx.external` with the same record shape.
* **Vectors are stored twice in a world**: in the inference record (JSON in the `ext` event, or an array blob with
  the substrate) and in the `embed.recorded` event that fills the `embeddings` table (about 2 KB per text, 13 KB per
  video vector, base64).
* **Devices differ in the last bits** (fp32 CPU vs GPU, cosine > 0.9995). A world is exact through its records; the
  shared disk cache returns whichever device computed a key first.
* **Synthetic validation.** The separation suites are generated artifacts (rendered text, drawn scenes, synthetic
  speech and music, slideshow videos, small programs), not natural media; ratios on natural content will be lower.
* **Model limits.** Whisper-tiny is forced to English and transcribes the first 60 s; AST reads at most three 10.24 s
  windows; a video is 8 frames (scene changes between them are missed, cut statistics come from 4 fps grey frames);
  CLIP pads non-square images (thin banners become small); the code encoder uses a general sentence model and
  regular expressions for languages other than Python.
* **The quality audit is name-based**: a score under an unrelated name would not be caught, and the content/participant
  scope is a list (`PARTICIPANT_SCOPE`) that new packages must be added to. Lines may opt out only with a visible
  `# not-a-content-score: <reason>` pragma, which the audit reports.
* **Media sandboxing** is resource limits plus protocol/demuxer allow-lists, not the Landlock/seccomp sandbox used for
  agent code; FFmpeg runs as the simulator's user. HTML "lite" rendering has no CSS layout (floats, grids, tables
  become blocks) and no images.
* **Regenerating a media tool run re-runs the tool** and checks the output's SHA-256 against the record (outputs are
  bit-exact); a different FFmpeg or Pillow version makes regeneration fail loudly instead of diverging silently.
